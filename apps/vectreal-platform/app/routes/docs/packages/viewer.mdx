## Quick start

```tsx
import { useLoadModel } from '@vctrl/hooks/use-load-model'
import { VectrealViewer } from '@vctrl/viewer'
import '@vctrl/viewer/css'

function App() {
  const { file } = useLoadModel()
  return <VectrealViewer model={file?.model} />
}
```

Or, with a model already hosted somewhere, give it the address:

```tsx
<VectrealViewer src="https://cdn.example.com/models/chair.glb" />
```

> You **must** import the CSS bundle (`@vctrl/viewer/css`) for the viewer to render correctly.

## Styling with `className`

`VectrealViewer`, `AnimationControls`, `CameraControls` and each `InfoPopover` part take a `className`. The viewer writes its own classes with Tailwind's `vv:` prefix, and its stylesheet contains only those, so a class you pass is styled by your stylesheet and nothing in the viewer's competes with it.

Where your class sets a property the viewer also sets on that element, the viewer drops its own class. `className="h-96"` replaces the container's full height. The match is by property, so two cases take more than you might expect:

- `px-2` replaces the controls' `p-1` padding on all four sides, not only the horizontal ones. Pass both axes if you change one.
- A class under a variant replaces the viewer's at every width and state: `md:h-96` drops the full height below `md` too. Pass the base as well, as in `h-full md:h-96`.

The match reads Tailwind's default scale and arbitrary values. A class from your own theme, such as `h-hero`, is not recognized and the viewer's own wins. Mark it important (`h-hero!`) and it wins instead.

One exception: the controls' surface (background, border, shadow and backdrop blur) comes from a stylesheet rule shared with the Vectreal editor, not from a class, and a class you pass does not override it.

The viewer declares none of Tailwind's theme variables, so content you render inside it, such as a custom `loader` or popover content, resolves `--spacing`, `--text-*` and `--ease-*` from your own theme.

**Upgrading:** earlier releases shipped unprefixed utilities such as `.flex` and `.hidden` in `@vctrl/viewer/css`. Two things change:

- A stylesheet that overrides one of the viewer's classes has to name the prefixed class: `.vctrl-viewer .h-full` becomes `.vctrl-viewer .vv\:h-full`. Passing your class through `className` is simpler and survives the next change of the viewer's classes.
- A page that styled its own markup with classes it never generated, and that only worked because the viewer's stylesheet happened to contain them, needs to generate those classes itself.

### Notes on content source

`model` is optional because you can also pass `src`, or render scene content via `children`. With none of them, nothing renders.

**Loading from a URL.** `src` covers the case where you have an address rather
than a loaded model. The viewer fetches the file, parses it and draws it, showing
`loader` meanwhile and `errorFallback` if it fails, and `children` render once
the model has. The parsers come from
`@vctrl/core` and load the first time `src` is used, so a page that only passes
`model` never downloads them. The host has to allow cross-origin reads. A `.gltf`
brings the buffers and images it references on its own origin. A URL with no
extension opens when its bytes are a GLB. A new address loads afresh, and a new
`srcOptions` object at the same address does not. For a URL someone else
supplied, pass `srcOptions={{ init: { credentials: 'omit' } }}`. To load through
your own state, with progress and errors in one place, use `useLoadModel`'s
`{ kind: 'url' }` source from `@vctrl/hooks` and pass `model` instead.

A still viewer stops drawing. Once the camera stops it renders a few dozen extra frames to smooth edges and settle ambient occlusion, then draws nothing until something changes. Moving objects are detected on their own, so `children` that animate in `useFrame` keep rendering. A child that changes only a material, a uniform or a texture must call `invalidate()` from `useThree`, the same contract React Three Fiber sets for on-demand rendering.

The editor affordances exist for editing surfaces such as the Publisher: `staticShadowBake`, `onShadowBakeReady`, and the hotspot props above - `selectedHotspotId`, `showInternalHotspots`, `showHiddenHotspots`, `onHotspotSelect`, `revealedHotspotId` and `onHotspotPositionSetterReady`. Public and embedded viewers omit them. Embedded viewers do pass the scene's saved bake as `bakedShadow`, so the shadow renders on load without re-baking.

`shadowLightEditable`, `editableLightRole` and `onShadowLightChange` are deprecated and go in the next major version: a light aimed on its own leaves the environment's bright region it was set against. Turn `lighting.environment.rotation` instead, which moves every light with the environment.

## Camera options (`CameraProps`)

`cameraOptions` accepts:

```ts
type CameraProps = {
  activeCameraId?: string
  cameras?: Array<PerspectiveCameraProps & {
    cameraId: string
    name: string
    kind?: 'scene' | 'hotspot'
    initial?: boolean
    target?: [number, number, number]
  }>
  sceneTransition?: {
    type: 'linear' | 'object_avoidance' | 'none'
    duration?: number
    easing?: 'linear' | 'ease_in' | 'ease_out' | 'ease_in_out'
  }
  showControls?: boolean
}
```

Each camera entry extends `PerspectiveCameraProps` from Drei and adds viewer-specific camera switching metadata. Transitions between cameras are configured once at the scene level via `sceneTransition`, not per camera. A visitor whose system asks for reduced motion (`prefers-reduced-motion: reduce`) gets every camera switch instantly, whatever the transition. `showControls: false` keeps the viewer's camera switcher off for this scene; absent, it shows whenever there are two or more scene cameras.

```jsx
<VectrealViewer
  cameraOptions={{
    activeCameraId: 'default',
    sceneTransition: {
      type: 'linear',
      duration: 900,
      easing: 'ease_in_out'
    },
    cameras: [
      {
        cameraId: 'default',
        name: 'Default',
        initial: true,
        position: [0, 5, 8],
        fov: 55,
        near: 0.1,
        far: 1000
      }
    ]
  }}
/>
```

### Sampling a flight outside the viewer

`sampleCameraFlight` is the flight between two cameras as a pure function of raw progress, the same one the viewer samples every frame. A renderer that draws frames itself, out of order or at a fixed rate, calls it per frame and gets the path the viewer flies. Import it from `@vctrl/viewer/camera-flight`, which needs only `three`, or from the package root.

```ts
import { sampleCameraFlight } from '@vctrl/viewer/camera-flight'
import { Sphere, Vector3 } from 'three'

const flight = {
  type: 'object_avoidance', // or 'linear'
  from: { position: new Vector3(0, 1, 4), target: new Vector3(), fov: 50 },
  to: { position: new Vector3(0, 0.3, -1), target: new Vector3(0, 0, -0.4), fov: 40 },
  easing: 'ease_in_out',
  bounds: new Sphere(new Vector3(), 0.6) // the model's world bounding sphere
}

// rawProgress = elapsed / duration, 0 to 1, linear in time
const { position, target, fov, quaternion } = sampleCameraFlight(flight, rawProgress)
```

`quaternion` looks at `target`, so it can be applied to a camera directly. Pass a reused frame object as the third argument to sample without allocating. `easeFlightProgress` is the easing on its own.

## Lighting (`LightingSettings`)

A scene is lit by an environment map and up to three studio lights, and every
shadow comes from those lights: they light the model, shadow the model, and
cast its shadow on the ground. There is no shadow opacity or direction to set;
to change a shadow, change its light. The type and the migration rules live in
[`@vctrl/core`](/docs/packages/core#scene-lighting).

```jsx
<VectrealViewer
  lighting={{
    environment: { map: 'studio-soft', intensity: 0.8, rotation: 0 },
    lights: [
      { role: 'key', azimuth: 40, elevation: 45, size: 15, intensity: 0.7 },
      { role: 'fill', azimuth: -60, elevation: 25, size: 60, intensity: 0.2 },
      { role: 'rim', azimuth: 170, elevation: 30, size: 10, intensity: 0.5 }
    ],
    ground: { enabled: true },
    background: { type: 'color', color: '#f4f4f5' }
  }}
/>
```

| Field | What the viewer does with it |
|---|---|
| `environment.map`, `resolution` | Loads the hosted HDR that lights the model and gives it reflections |
| `environment.intensity` | Brightness of the environment, and with it of every light |
| `environment.rotation` | Turns the map, its reflections, the background and the lights together, in degrees |
| `lights[]` | One directional light each, at most one per `role` (`key`, `fill`, `rim`). `azimuth` is degrees around the vertical axis (0 lights from +Z, 90 from +X, before the rotation), `elevation` degrees above the horizon |
| `lights[].intensity` | Relative to the environment's own light, which the viewer measures from the map: 1 is as bright as the whole environment |
| `lights[].size` | Angular diameter in degrees. The ground shadow is baked from it exactly; the model's own shadow is softened by the shadow-map filter, which only approximates it |
| `ground.enabled` | Bakes the ground shadow from every light, weighted by strength. Ground every light is blocked from keeps `1 / (1 + Σ strength × sin(elevation))` of its light. With no lights, the ground darkens only where the model hides the sky |
| `background` | `environment` (with `intensity` and `blur`), a `color` or `gradient` stage painted behind the canvas (`#rrggbb` hex), or `none` for a transparent viewer |
| `occlusion` | Screen-space ambient occlusion (N8AO): `off` or `live`, with `live.intensity` and `live.atRest` (draw it only once the view is still) |

While the model animates, the ground switches to a live contact shadow that
follows the moving geometry.

### Baked lights

A model published with its studio lights baked carries a light map on each
baked material, under the `VECTREAL_lightmap` extension (see
[`@vctrl/core`](/docs/packages/core#light-bake)). The viewer draws a material's
map while the scene's `lighting` has the signature the map was baked from, in
place of the lights' live diffuse light. Their highlights stay live. The map is
scaled by the environment's measured light and `environment.intensity`, as the
live lights are. The lights keep their shadow maps, which then shade only
their highlights. Change a light or the rotation, or turn `bake.lights` off,
and no map matches any more: the viewer draws the lights live until the model
is baked again. This applies to the model the viewer draws, including
`displayedModel`.

### Before `lighting`: `envOptions` and `shadowsOptions`

Both props still work and are deprecated. Without `lighting`, the viewer reads
them through `resolveLighting`: the environment carries over exactly, and the
shadow's own light becomes the key, placed where it stood and capped at the
environment's strength. That light used to reach only the ground; it now
lights the model too. Fields that only tuned the old shadow (`opacity`,
`alphaTest`, `contact`, `frames`, `resolution`) are no longer read.
`envOptions.files` still names a custom environment map, with or without
`lighting`.

A viewer released before `lighting` still renders a newly saved scene: its
embed manifest carries the legacy `environment` and `shadows` derived from
`lighting` by `toLegacyLighting` in `@vctrl/core`. That viewer knows one light,
which shadows only the ground, and no rotation, so it shows the environment
unturned, the key as the shadow's direction and size, and every lit light in
the shadow's darkness. Fill and rim lights, and light on the model, need this
release. The derived keys go away with the deprecated props in the next major.

## Bounds

### boundsOptions (`BoundsProps`)

`BoundsProps` is forwarded to Drei `Bounds`. The viewer defaults are:

| Option | Default |
|---|---|
| `clip` | `false` |
| `margin` | `1.5` |
| `maxDuration` | `0` |

`clip` is `false` because near/far planes are managed per frame in `SceneModel`, so Drei's `Bounds` is deliberately kept from writing them.

`fit` is accepted for API compatibility but ignored: `SceneBounds` always passes `fit={false}` to Drei's `Bounds` because `SceneCamera` frames the first view itself. That framing uses `margin`, and it is applied in one step, so `maxDuration` does not animate it.

Example:

```jsx
<VectrealViewer
  boundsOptions={{
    clip: false,
    margin: 1.25,
    maxDuration: 300
  }}
/>
```

## Screenshot callbacks

`VectrealViewer` supports two screenshot-related callbacks:

- `onScreenshot(dataUrl)` receives a data URL each time a screenshot is captured. The default encoding is WebP at quality `0.86`; `mimeType` accepts `'image/webp'` or `'image/jpeg'`.
- `onScreenshotCaptureReady(capture)` gives you a capture function that can be stored and called from external UI.

The callback types are exported from `@vctrl/viewer` as `SceneScreenshotCapture` and `SceneScreenshotOptions`.

`SceneScreenshotOptions`:

| Option | Type | Default | Description |
|---|---|---|---|
| `width` | `number` | `1280` | Output width in pixels |
| `height` | `number` | `720` | Output height in pixels |
| `mimeType` | `'image/jpeg' \| 'image/webp'` | `'image/webp'` | Output format |
| `quality` | `number` | `0.86` | Image quality hint for lossy output |
| `mode` | `'auto-fit' \| 'viewport'` | `'auto-fit'` | Capture strategy |
| `targetCameraId` | `string` | none | Transition to this camera, capture, then return to the original camera |

## Camera snapshot callback

`onCameraSnapshotCaptureReady(capture)` gives you a function that captures the current viewer camera pose as `{ position, rotation, target, fov }`.

This is useful when building camera authoring tools or when you need to persist the current camera framing from surrounding UI.

## Runtime commands and events

`VectrealViewer` exposes a small runtime interaction surface for app layers that need to coordinate camera state or viewer interactivity without reaching into internal scene objects.

### Commands

`onCommandExecutorReady(executor)` receives a `ViewerCommandExecutor` with `execute(command)`.

Commands can be sent as soon as the executor arrives. One the scene cannot run yet, because the model is still loading or the viewer is out of view (the canvas mounts only near the viewport), is held and runs once it can. Of several held commands of one type, only the last one runs.

Current commands:

| Command | Payload | Effect |
|---|---|---|
| `activate_camera` | `{ cameraId: string }` | Transitions to one of the configured scene cameras |
| `return_to_scene_view` | `{}` | Leaves a hotspot's camera for the scene camera the visitor was on before, or the default. Does nothing away from a hotspot |
| `set_controls_enabled` | `{ enabled: boolean }` | Temporarily enables or disables orbit interaction |
| `set_transition` | `{ transitionType: 'none' \| 'linear' \| 'object_avoidance'; duration?: number; easing?: string }` | Overrides the active camera transition |
| `set_auto_rotate` | `{ enabled: boolean; speed?: number }` | Toggles and configures auto-rotation |
| `set_controls_options` | `{ zoom?: boolean; pan?: boolean }` | Enables or disables zoom/pan interaction at runtime |

### Events

`onInteractionEvent(event)` receives a `ViewerInteractionEvent`. The runtime emits six of them:

| Event | Payload | Meaning |
|---|---|---|
| `viewer_ready` | none | The camera has framed the model and takes commands. Emitted again when the canvas remounts or the camera settings change |
| `initial_framing_completed` | `{ cameraId: string \| null }` | Initial framing and stabilization completed |
| `camera_changed` | `{ cameraId: string }` | Active camera changed |
| `hotspot_activated` | `{ hotspotId: string; cameraId: string \| null }` | A visitor activated a hotspot |
| `animation_state_changed` | `{ playing: boolean; activeClipId: string \| null; complete: boolean }` | Animation playback started, stopped or advanced |
| `animation_clip_finished` | `{ clipId: string }` | One animation clip ran to its end |
| `environment_load_failed` | `{ files: string[] }` | The environment map could not be loaded; the scene is lit by a neutral room instead |
| `environment_loaded` | `{ files: string[] }` | The environment map loaded, including after an earlier failure |
| `shadow_bake_skipped` | `{ reason: 'touch_device' \| 'over_budget'; estimatedDraws: number }` | With `liveShadowBake="within-budget"`, the viewer drew a contact shadow instead of baking the ground shadow live. Publishing the scene again stores a bake every device shows |

`ViewerInteractionEvent` also declares `model_loaded` and `auto_rotate_changed`. Both belong to the union a handler has to narrow, and neither is emitted by the current runtime.

### Example

```tsx
import { useRef } from 'react'
import {
  type ViewerCommandExecutor,
  VectrealViewer
} from '@vctrl/viewer'

function ViewerRuntimeExample({ model }: { model: object }) {
  const executorRef = useRef<null | ViewerCommandExecutor>(null)

  return (
    <>
      <button
        onClick={() =>
          executorRef.current?.execute({
            type: 'activate_camera',
            cameraId: 'overview'
          })
        }
      >
        Go to overview
      </button>
      <button
        onClick={() =>
          executorRef.current?.execute({
            type: 'set_controls_enabled',
            enabled: false
          })
        }
      >
        Lock controls
      </button>
      <VectrealViewer
        model={model as never}
        onCommandExecutorReady={(executor) => {
          executorRef.current = executor
        }}
        onInteractionEvent={(event) => {
          console.log('viewer event', event)
        }}
      />
    </>
  )
}
```

## Scene components and defaults

`@vctrl/viewer` also exports the scene components `VectrealViewer` composes, each with the
default options object it merges over. Import them to build a custom canvas, or to start
from a viewer default and override a field:

| Export | Default options |
|---|---|
| `SceneBounds` | `defaultBoundsOptions` |
| `SceneCamera` | `defaultCameraOptions` |
| `SceneControls` | `defaultControlsOptions` |
| `SceneEnvironment` | `defaultEnvOptions` |
| `SceneShadows` | none: pass resolved `lighting`, or legacy shadow props it resolves itself |
| `SceneHotspots` | none |
| `SceneModel` | none |
| `ScenePostProcessing` | none |

```tsx
import { defaultControlsOptions, VectrealViewer } from '@vctrl/viewer'

<VectrealViewer
  controlsOptions={{ ...defaultControlsOptions, autoRotate: true }}
/>
```

The info popover slot is built from `InfoPopover`, `InfoPopoverTrigger`,
`InfoPopoverContent`, `InfoPopoverText` and `InfoPopoverCloseButton`, all
exported from the same entry point. The content is yours: these primitives
carry no branding of their own.

Whatever you pass to `popover` is unmounted, not merely hidden, until the
viewer reaches `ready` - after the loader's cross-fade, or immediately when you
pass `loader={null}` and there is no cross-fade to wait for. Slot content
therefore cannot hold state it needs to survive the load, and a scene that
never finishes framing never mounts the slot at all.

The slot renders as a bare sibling of the canvas and supplies no positioning of
its own. Note that the viewer's own container is not positioned either, so
`InfoPopover`'s `absolute bottom-0` resolves against whatever positioned
ancestor you give it: put the viewer in a `relative` wrapper if you use the
slot, or position your own content some other way.

The built-in controls (camera switcher, playback, the way back from a hotspot's
camera, the info button and card, hotspot cards and labels) are drawn in
Vectreal's own panel style, and their palette is declared on the viewer's root
under its `light` or `dark` class. Content you render inside the viewer, such as
a custom `loader` or your popover content, inherits that palette, so tokens it
shares a name with (`--background`, `--foreground`, `--muted-foreground`,
`--border` and the rest of a shadcn-style set) resolve to the viewer's values
there rather than your page's. Style that content with your own names, or set
`theme` to match your page. The hotspot marker keeps its own
`--vctrl-hotspot-*` tokens, which you can override on the container.

The viewer ships no font and names none: its text takes the typeface of the
page it sits on. To give it another, set `font-family` on the viewer's container
(its `className`, or an element around it).

## Integration with `@vctrl/hooks`

The viewer is designed to be used alongside [`@vctrl/hooks`](/docs/packages/hooks). Wrap your app with `ModelProvider` and consume the loaded model via `useModelContext`, then pass it to the `model` prop:

```tsx
import { ModelProvider, useModelContext } from '@vctrl/hooks/use-load-model'
import { VectrealViewer } from '@vctrl/viewer'
import '@vctrl/viewer/css'

function Scene() {
  const { file } = useModelContext(false)
  return <VectrealViewer model={file?.model} />
}

export default function App() {
  return (
    <ModelProvider>
      <Scene />
    </ModelProvider>
  )
}
```

> `VectrealViewer` does not read the loaded model from context automatically. You must always pass the `model` prop explicitly. `useModelContext` (or `useLoadModel`) gives you `file?.model` to forward.
