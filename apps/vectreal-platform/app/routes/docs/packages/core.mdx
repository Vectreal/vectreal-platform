# @vctrl/core

Isomorphic 3D model processing. This package provides the shared loading, optimization, and export pipeline used by other Vectreal packages, and runs in Node.js, browsers, and Web Workers alike.

---

## Installation

```bash
npm install @vctrl/core
# or
pnpm add @vctrl/core
```

**Module format:** ES modules only. Import it from any bundler, browser or Node.js. `require()` also loads it on Node.js 20.19, 22.12 and later, but three.js and glTF-Transform then load as ES modules too, separately from a `require('three')` of your own, so their objects fail each other's `instanceof` checks. Use `import` when you pass those objects in.

{/* claims
present packages/core/package.json "type": "module"
absent packages/core/package.json "require"
present packages/core/src/model-optimizer/types.ts primitivesCount: BeforeAfterMetric
present packages/core/src/model-optimizer/types.ts meshBytes: BeforeAfterMetric
present packages/core/src/model-optimizer/types.ts textureBytes: BeforeAfterMetric
*/}

> **Texture compression is encoder-injectable.** Nothing here hard-depends on
> Sharp.

`@vctrl/core` runs in Node.js, browsers and edge runtimes, and picks its encoder
to match:

- **Node.js** uses [Sharp](https://sharp.pixelplumbing.com) if you install it
  (`npm install sharp`). It is an optional add-on.
- **Anywhere else**, pass your own `TextureCompressOptions.encoder` and Sharp is
  never imported. `@vctrl/hooks` ships an `OffscreenCanvas`-based one as
  `createBrowserTextureEncoder()`, injects it for you inside `useOptimizeModel`,
  and exports it for direct use.
- **With neither**, `compressTextures` falls back to a basic optimization.

## `ModelLoader`

```typescript
import { ModelLoader } from '@vctrl/core/model-loader'
import { readFile } from 'node:fs/promises'

const loader = new ModelLoader()

// From a file path
const result = await loader.loadFromFile('model.glb')

// From a Node.js Buffer
const buffer = await readFile('model.glb')
const resultFromBuffer = await loader.loadFromBuffer(
  new Uint8Array(buffer),
  'model.glb'
)

// Convert directly to Three.js scene
const sceneResult = await loader.loadToThreeJS('model.glb')
```

### Primary methods

| Method | Description |
|---|---|
| `loadFromFile(input, assetFiles?)` | Load from a file path (Node) or a browser `File`. `assetFiles` are the files that arrived beside it, so a dropped OBJ finds its `.mtl` and textures instead of rendering grey |
| `loadFromBuffer(buffer, fileName, siblings?)` | Load from `Uint8Array` data |
| `loadGLTFWithAssets(...)` / `loadGLTFWithFileAssets(...)` | Load GLTF with external resources |
| `documentToThreeJS(document, modelResult)` | Convert glTF-Transform `Document` to Three.js scene |
| `parseGLTFJsonToThreeJS(json, assets)` | Parse glTF JSON straight to Three.js, for a saved scene |
| `loadToThreeJS(input, assetFiles?)` | Load and convert to Three.js scene |
| `loadGLTFWithAssetsToThreeJS(...)` | GLTF + assets directly to Three.js |
| `parseGLBToThreeJS(bytes)` | Parse a GLB straight to Three.js, for a model that will never be edited |
| `prepareDracoDecoder()` / `prepareKtx2Transcoder()` | Download a decoder ahead of the first model that needs it |

Every path decodes Draco, meshopt and KTX2 (`KHR_texture_basisu`). The Draco
decoder and the KTX2 transcoder are fetched from `/draco/` and `/basis/` unless
the constructor's `dracoDecoderPath` or `ktx2TranscoderPath` says otherwise; the
meshopt decoder ships inside the package.

Asking which formats are accepted is `@vctrl/core/model-formats`, not the loader.
`isSupportedFormat` and `getSupportedExtensions` were removed for that reason:
they were a second statement of the set, and they disagreed with the first one on
casing, so `MODEL.GLB` was rejected by the guard standing in front of a loader
that would have read it. Use `isImportableFileName(fileName)` or
`modelFormatForFileName(fileName)`.

### Fetching a model from a URL

```typescript
import { fetchModelFiles, ModelLoader } from '@vctrl/core/model-loader'

const [model, ...siblings] = await fetchModelFiles('https://cdn.example.com/chair.gltf')
const loader = new ModelLoader()
const result = model.name.toLowerCase().endsWith('.gltf')
  ? await loader.loadGLTFWithAssetsToThreeJS(model, siblings)
  : await loader.loadToThreeJS(model, siblings)
```

`fetchModelFiles(url, { init?, onProgress? })` returns the files a drop of the
same model would give, model first, so they load through the path a dropped
file takes. A `.gltf` brings the buffers and images it references on its own
origin; a reference on another host is skipped and the loader reports it
missing. A URL with no file extension is read as a GLB when its bytes are one.
`init` goes with every request, and an abort through its `signal` rejects with the signal's reason. `onProgress` reports the model file's download from 0 to 1 when the host sends a `Content-Length`; a `.gltf`'s other files download after it without reporting. A failure is a
`ModelFetchError` with `kind` `unreachable`, `http` (and `status`), `unrecognized` or `invalid` (not a URL, or relative with no page to resolve it against); its message and `host` name the host only, never the address, which can be a signed link. The host has to allow cross-origin reads.

`documentToThreeJS` requires both the `Document` and the original `ModelLoadResult` metadata object:

```typescript
const loaded = await loader.loadFromFile('model.glb')
const threeResult = await loader.documentToThreeJS(loaded.data, loaded)
```

## `ModelOptimizer`

```typescript
import { ModelOptimizer } from '@vctrl/core/model-optimizer'

const optimizer = new ModelOptimizer()

// Load a model into the optimizer
await optimizer.loadFromBuffer(modelBuffer)

// Run optimizations
await optimizer.simplify({ ratio: 0.5 })
await optimizer.deduplicate()
await optimizer.quantize({ quantizePosition: 14 })
await optimizer.compressTextures({ quality: 80 })

// Export the result
const optimizedBuffer = await optimizer.export()
```

### Loading

| Method | Description |
|---|---|
| `loadFromThreeJS(model)` | Load a Three.js `Object3D` |
| `loadFromBuffer(buffer)` | Load GLB binary data |
| `loadFromFile(path)` | Load a GLB from a file path (Node) |
| `loadFromJSON(json)` | Load a glTF `JSONDocument` with its resources |
| `loadFromGLTFWithAssets(gltfBytes, assets)` | Load `.gltf` bytes plus a URI-to-bytes asset map, bypassing Three.js so the original texture URIs survive |

### Optimization passes

| Method | Options | Description |
|---|---|---|
| `place(opts)` | `PlacementOptions` | Center the model on the ground at the origin, optionally at a real-world size |
| `simplify(opts)` | `SimplifyOptions` | Mesh simplification |
| `deduplicate(opts)` | `DedupOptions` | Remove duplicate accessors, meshes, textures and materials |
| `quantize(opts)` | `QuantizeOptions` | Reduce vertex attribute precision |
| `optimizeNormals(opts)` | `NormalsOptions` | Recompute/normalize normal data |
| `compressTextures(opts)` | `TextureCompressOptions` | Texture compression via an injectable encoder (Sharp on Node.js by default) |
| `compressGeometry(opts)` | `DracoOptions` | Replace the loaded document with a Draco-compressed copy |
| `optimizeAll(opts)` | see below | Run every pass above except placement and Draco, in a fixed order |

### Draco measurement

| Method | Description |
|---|---|
| `measureDracoCompression(opts)` | Draco-encode a throwaway clone and return a `DracoCompressionReport`, leaving the loaded document untouched |
| `setDracoReport(report)` | Adopt a measurement produced elsewhere, for example inside the geometry Web Worker. `null` clears it |

`compressGeometry` skips the swap and warns when the measurement's `isWorthApplying` is
false, which happens on small or texture-dominated models where Draco produces a larger
GLB than leaving the geometry uncompressed.

### Textures

| Method | Description |
|---|---|
| `listTextureDescriptors()` | `TextureDescriptor[]`: index, canonical file name, name, MIME type, byte length |
| `getTexturePayload(index)` | `TextureBinaryPayload`: the descriptor plus the image bytes |
| `replaceTexturePayload(index, image, mimeType, fileName?)` | Swap one texture's bytes and re-sync its URI and name |
| `normalizeAllTextureURIs(doc?)` | Canonicalize every texture URI and name. Passing a document also adopts it as the loaded one |

### Report and state

| Method | Description |
|---|---|
| `getReport()` | Before/after optimization metrics |
| `getBaseline()` / `setBaseline(baseline)` | Read or restore the load-time baseline the report is measured against. Restoring matters after a worker hands back optimized bytes, so the baseline is not re-taken on them |
| `getAppliedOptimizations()` / `addAppliedOptimization(name)` / `setAppliedOptimizations(names)` | The list of applied steps carried in the report |
| `export()` / `exportJSON()` | Export the optimized GLB or glTF JSON document |
| `hasModel()` / `reset()` | Model state utilities |
| `document` | The loaded glTF-Transform `Document`. Throws if nothing is loaded |
| `onProgress(callback)` | Receive `OperationProgress` updates from every pass |

### Optimization options reference

#### `place(options?: PlacementOptions)`

Centers the model on X and Z and stands its lowest point on y = 0, which is where AR viewers put the floor. The scene's contents move under one new parent node, so meshes, their own transforms and animations are untouched. Unlike the other passes it is kept even though that node makes the file slightly larger.

| Option | Type | Default | Notes |
|---|---|---|---|
| `longestEdgeMeters` | `number` | none | Scales uniformly so the longest bounding-box edge has this real-world length. Omitted, the model keeps its size. |

#### `simplify(options?: SimplifyOptions)`

| Option | Type | Default | Notes |
|---|---|---|---|
| `ratio` | `number` | `0.5` | Target simplification ratio. Lower values are more aggressive. |
| `error` | `number` | `0.001` | Allowed geometric error threshold for simplification. |

#### `deduplicate(options?: DedupOptions)`

Removes duplicate accessors, meshes, textures and materials via glTF-Transform `dedup()`.

#### `quantize(options?: QuantizeOptions)`

| Option | Type | Notes |
|---|---|---|
| `quantizePosition` | `number` | Forwarded to glTF-Transform `quantize()` |
| `quantizeNormal` | `number` | Forwarded to glTF-Transform `quantize()` |
| `quantizeColor` | `number` | Forwarded to glTF-Transform `quantize()` |
| `quantizeTexcoord` | `number` | Forwarded to glTF-Transform `quantize()` |

#### `optimizeNormals(options?: NormalsOptions)`

| Option | Type | Notes |
|---|---|---|
| `overwrite` | `boolean` | Recompute normals even when normals already exist |

#### `compressGeometry(options?: DracoOptions)` and `measureDracoCompression(options?: DracoOptions)`

| Option | Type | Default | Notes |
|---|---|---|---|
| `method` | `'edgebreaker' \| 'sequential'` | `'edgebreaker'` | Draco encoding method |
| `encodeSpeed` | `number` | `5` | 0 to 10. Slower encoding produces smaller output |
| `decodeSpeed` | `number` | `5` | 0 to 10 |
| `quantizePosition` | `number` | `14` | Position quantization bits |
| `quantizeNormal` | `number` | `10` | Normal quantization bits |
| `quantizeColor` | `number` | `8` | Color quantization bits |
| `quantizeTexcoord` | `number` | `12` | Texture coordinate quantization bits |
| `quantizeGeneric` | `number` | `12` | Generic attribute quantization bits |

Defaults come from glTF-Transform's `draco()`. Draco encoding requires a browser or Web
Worker environment.

#### `compressTextures(options?: TextureCompressOptions)`

`TextureCompressOptions` has exactly four fields:

| Option | Type | Current behavior |
|---|---|---|
| `encoder` | `unknown` | Custom image encoder matching the Sharp constructor API. When provided, Sharp is never imported, which is what makes browser and edge use possible |
| `resize` | `[number, number]` | Maximum texture size |
| `targetFormat` | `'webp' \| 'jpeg' \| 'png'` | Target texture format |
| `quality` | `number` | Encoder quality |

There is no server round-trip in this path and no `serverOptions`: compression happens in-process using whichever encoder is in play.

The pass compresses a copy of the document and commits it in one step, so the document only ever holds a finished result:

| Outcome | Document | Recorded as `texture compression` | Throws |
|---|---|---|---|
| Every texture compressed | The compressed copy | Yes | No |
| Some failed | The copy: compressed textures replaced, failed ones as they were | Yes | `TextureCompressionError`, `isPartial === true` |
| None compressed | Unchanged | No | `TextureCompressionError`, `isPartial === false` |
| Another model or document taken while it ran | Unchanged | No | `SupersededError` |

When Sharp is unavailable, `compressTextures` falls back to basic texture optimization (`dedup` + `prune`) instead of throwing, and records only that.

#### `optimizeAll(options?)`

```typescript
await optimizer.optimizeAll({
  simplify: { ratio: 0.6 },
  dedup: {},
  quantize: { quantizePosition: 14 },
  normals: { overwrite: false },
  textures: { targetFormat: 'webp', quality: 80 },
})
```

Execution order is fixed:

1. `simplify` (unless `false`)
2. `deduplicate` (unless `false`)
3. `quantize` (unless `false`)
4. `optimizeNormals` (unless `false`)
5. `compressTextures` (unless `false`)

Every pass runs with its own defaults unless you set it to `false`, so `optimizeAll()`
with no arguments runs all five. Draco is not part of `optimizeAll`: call
`compressGeometry` for it.

Texture compression needs an encoder. Outside Node.js, pass one as `textures.encoder` or
set `textures: false`; without one the pass warns and falls back to a dedup and prune of
the texture set.

### `getReport()` return structure

`getReport()` includes:

- `originalSize`, `optimizedSize`
- `compressionRatio` (`originalSize / optimizedSize`)
- `appliedOptimizations`
- `stats`, before/after metrics: `verticesCount`, `primitivesCount`, `materialsCount`, `meshesCount`, `meshBytes` (mesh payload size in bytes), `texturesCount`, `textureBytes`, and `textureResolutions`
- `draco`, a `DracoCompressionReport`, only when a Draco measurement has been recorded. Draco compression is deferred until write time, so `stats.meshBytes` always reflects uncompressed geometry

```typescript
const report = await optimizer.getReport()
console.log(report.stats.textureResolutions.before)
console.log(report.stats.textureResolutions.after)
```

## `ModelExporter`

```typescript
import { ModelExporter } from '@vctrl/core/model-exporter'

const exporter = new ModelExporter()

// Export Three.js scene as binary GLB
const glb = await exporter.exportThreeJSGLB(scene)

// Export Three.js scene as glTF + assets map
const gltf = await exporter.exportThreeJSGLTF(scene)

// Package glTF + assets into zip
const zip = await exporter.createZIPArchive(gltf, 'model')
```

### Primary methods

| Method | Description |
|---|---|
| `exportDocumentGLB(document)` | Export glTF-Transform `Document` to GLB |
| `exportDocumentGLBDraco(document, options?)` | Export `Document` to GLB with Draco geometry compression |
| `exportDocumentGLBForPublish(document, options?)` | Export the GLB a scene is published as: `options.textures` rewrites the textures of a clone once (the Publisher passes `compressTexturesToKtx2` from `@vctrl/core/model-optimizer`), then `options.draco` encodes the geometry in Draco or meshopt, whichever `pickGeometryCodec` chooses by gzipped size |
| `exportDocumentGLTF(document, options?)` | Export `Document` to GLTF JSON + assets. `options.draco` runs the same compression as `exportDocumentGLBDraco`, but note the nesting differs: there, the whole `options` argument is the Draco options |
| `exportThreeJSGLB(object)` | Export Three.js object to GLB |
| `exportThreeJSUSDZ(object)` | Export Three.js object to USDZ |
| `exportThreeJSGLTF(object)` | Export Three.js object to GLTF JSON + assets |
| `createZIPArchive(result, baseName?)` | Bundle GLTF + assets into zip |
| `saveToFile(result, filePath)` | Persist any export result on the Node filesystem |

## Use in API routes

The Vectreal Platform runs this pipeline in a browser Web Worker, not on the server; its server modules import only types and constants from `@vctrl/core`. The package works the same way in a Node.js route if that suits your app better. A minimal example:

```typescript
import { ModelOptimizer } from '@vctrl/core/model-optimizer'

export async function POST(request: Request) {
  const formData = await request.formData()
  const file = formData.get('file') as File

  const buffer = Buffer.from(await file.arrayBuffer())

  const optimizer = new ModelOptimizer()
  await optimizer.loadFromBuffer(new Uint8Array(buffer))
  await optimizer.simplify({ ratio: 0.7 })
  await optimizer.compressTextures({ quality: 80 })

  const optimized = await optimizer.export()

  return new Response(optimized, {
    headers: { 'Content-Type': 'model/gltf-binary' },
  })
}
```

## Scene lighting

A scene is lit by an environment map and up to three studio lights, and every
shadow it shows comes from those lights. `SceneSettings.lighting` stores that,
typed as `LightingSettings`:

| Field | Meaning |
|---|---|
| `environment` | The HDR (`map`), its `resolution`, its `intensity`, and a `rotation` in degrees that turns the lights with it |
| `lights` | Up to `MAX_SCENE_LIGHTS` (3), one per `role`: `key`, `fill` or `rim`. Each has an `azimuth` and `elevation` in degrees, a `size` (angular diameter, which sets how soft its shadows are), an `intensity` and a `color` |
| `ground` | Whether a floor under the model receives its shadows |
| `background` | The environment map, a `color` or `gradient` stage, or `none` |
| `occlusion` | Ambient occlusion: `off`, `live` (screen space, every frame) or `baked` (raytraced into the model's textures when it is published) |
| `bake` | `lights: true` bakes the studio lights into a light map when the scene is published; see [Light bake](#light-bake) |

A light's `intensity` is relative to the environment's own diffuse light: 1 is as
bright as the whole environment. So the environment's brightness scales every
light, and a shadow's darkness follows from the ratio alone: ground a light
cannot reach keeps `1 / (1 + intensity × sin(elevation))` of the light it would
get, so `1 / (1 + intensity)` for a light straight overhead. There is no
shadow opacity or direction to set; to change a shadow, change its light.

Read lighting only through `resolveLighting(settings)`. It returns a
`ResolvedLighting` with every field filled, and it also answers for a scene saved
before `lighting` existed, by migrating its `environment` and `shadows`. The
shadow's own light becomes the key, placed where that light stood, about as
soft, and as strong as the old shadow was dark, up to the strength of the whole
environment. That light used to reach only the ground; now it lights the model
too, so a migrated scene's model gets brighter on the lit side and its darkest
shadows come out lighter. A scene whose shadows were off gets no light and looks
as it did.

```ts
import { resolveLighting } from '@vctrl/core'

const { environment, lights, ground } = resolveLighting(scene.settings)
```

`@vctrl/viewer` draws every scene through `resolveLighting`: pass `lighting`, or
the legacy `envOptions` and `shadowsOptions`, which stay readable for every
scene saved before `lighting`. See [Lighting](/docs/packages/viewer#lighting-lightingsettings)
for what the viewer does with each field.

### Lighting setups

`LIGHTING_SETUPS` holds the setups the Lighting tool offers, each a whole look:
a map, up to three lights, their sizes and the balance between them. Each light
stands on one of its map's own bright regions, so the reflection of a softbox or
the sun on a glossy surface sits where the light that casts the model's shadow
stands. Turning a setup (`environment.rotation`) turns the map and its lights
together.

The regions are measured, not placed by eye. `ENVIRONMENT_LIGHTS` lists every
hosted map's brightest regions as a direction, a size and a share of the map's
light; `pnpm nx run vectreal-platform:measure-environment-lights` reads the maps
and writes it again when a map changes. An evenly lit map, such as
`outdoor-overcast`, has none, and its setup lights with the environment alone.

```ts
import { LIGHTING_SETUPS } from '@vctrl/core'

const product = LIGHTING_SETUPS.find(({ id }) => id === 'product')
scene.settings.lighting = product?.lighting
```

## Occlusion bake

`@vctrl/core/occlusion-bake` raytraces ambient occlusion (the darkening in
creases, gaps and where parts touch) into each material's standard glTF
`occlusionTexture`. Any glTF viewer applies it, and it dims only environment
and ambient light, never a direct light. It runs in three steps:

```ts
import {
	bakeOcclusion,
	encodeOcclusionPng,
	planOcclusionBake,
	writeOcclusionBake
} from '@vctrl/core/occlusion-bake'

const plan = planOcclusionBake(document)
const baked = await bakeOcclusion(plan, renderer)
writeOcclusionBake(
	document,
	await Promise.all(
		baked.map(async (bake) => ({
			material: bake.material,
			image: await encodeOcclusionPng(bake),
			mimeType: 'image/png' as const
		}))
	)
)
```

**`planOcclusionBake(document)`** decides which materials can be baked. The bake
lives in the first UV set, so a material is baked only where one texel of it
means one place on the model. The others are listed in `plan.skipped` with the
reason:

| Reason | Meaning |
|---|---|
| `existing-occlusion` | It has an occlusion texture already, which is kept |
| `shared-geometry` | One mesh is placed more than once, by several nodes or GPU instancing, and each copy is occluded differently |
| `skinned` | A skin moves it, so no one bake fits every pose |
| `no-uv0` | It has no first UV set |
| `tiling-uvs` | Its UVs repeat the texture |
| `overlapping-uvs` | Two parts share texels, as mirrored halves usually do |

Every triangle in the scene casts occlusion, skipped or not, with three
exceptions (`castsOcclusion` answers for each part). Glass, meaning a material
with `KHR_materials_transmission` or blended transparency, is baked like any
surface but lets the rays through. A skinned or GPU-instanced part casts
nothing, because the viewer draws it somewhere other than where its node puts
it.

**`bakeOcclusion(plan, renderer, options?)`** needs a browser or a worker with a
`WebGLRenderer` (an `OffscreenCanvas` one works). It returns RGBA bytes per
material, row 0 at the top of the image. The options:

| Option | Default | Meaning |
|---|---|---|
| `resolution` | 512 | Texture width and height in pixels |
| `samples` | 256 | Rays per texel, at most 2048; more is smoother and slower |
| `distance` | 0.25 | How far a ray looks for an occluder, as a share of the scene's bounding box diagonal |

It runs the rays a few at a time and yields between them, so it does not freeze
the page or trip the GPU's watchdog.

**`writeOcclusionBake(document, images)`** stores each image as its material's
`occlusionTexture` at full strength, read from the first UV set.
`encodeOcclusionPng` makes the PNG in a browser or worker.

**`bakeOcclusionIntoDocument(document, renderer, options?)`** runs all of the
above in one step and returns which materials were baked and which skipped,
by name. `renderer` is a function that returns one, called only when some
material can be baked. Pass it to `ModelExporter.exportGlbForPublish` as `bake`, which
bakes the published copy before its textures are encoded:

```ts
await new ModelExporter().exportGlbForPublish(glb, {
	bake: async (copy) => {
		report = await bakeOcclusionIntoDocument(copy, () => renderer)
	},
	ktx2: { encode }
})
```

**`occlusionBakeSignature(plan, options)`** identifies a bake by everything that
changes its pixels, so a bake made for a preview can be reused while the
signature still matches.

## Light bake

`@vctrl/core/light-bake` raytraces the studio lights' diffuse light and soft
shadows into a light map for each material, in its first UV set. Each texel
samples every light that is on across its angular size, so a larger light casts
a softer shadow. Glass lets the light through, as in the occlusion bake.

```ts
import { resolveLighting } from '@vctrl/core'
import { bakeLightsIntoDocument } from '@vctrl/core/light-bake'

const report = await bakeLightsIntoDocument(
	document,
	resolveLighting(scene.settings),
	() => renderer
)
```

It plans with `planOcclusionBake(document, { existingOcclusion: 'bake' })`, so
it skips materials for the same reasons, except that an occlusion texture does
not stop it: bake ambient occlusion first, then the lights. It also skips a
double-sided material, as `double-sided`: one map cannot light both its sides.
And it skips, as `animated`, a material on a node an animation moves (or under
one), or with morph targets, because the map holds the rest pose's light.
While any part moves, is skinned or is GPU-instanced, it skips every other
material as `moving-shadows`: a map replaces the live shadows, and it cannot
hold the shadow of a part that moves or is drawn more than once. While an
alpha-masked part casts, it skips them as `cutout-shadows`, because the bake
traces every caster as solid. An unlit material is skipped as `unlit`. The options are
`resolution` (512) and `samples` (128 rays per light per texel).

There is no ratified glTF light map, so the map is written under a Vectreal
extension, `VECTREAL_lightmap`, on each material:

| Field | Meaning |
|---|---|
| `lightmapTexture` | A PNG, read from the first UV set. Each texel stores the square root of its share of `scale`, which keeps precision in the shadows |
| `scale` | The light a full texel holds: the lights' strengths added up, each by its brightest color channel. In the units of a light's `intensity`, relative to the environment |
| `signature` | `bakedLightsSignature` of the lighting it was baked from |

Read and write it through `IO_EXTENSIONS` from `@vctrl/core/light-bake`, which `ModelLoader`, `ModelOptimizer`
and `ModelExporter` register: glTF-Transform drops an extension it does not
know. `ModelLoader` hands it to three as the material's `lightMap`, at
`lightMapIntensity` 0 so that a renderer unaware of the encoding adds nothing,
with the `scale` and `signature` on `userData.vectrealLightmap`.
[`@vctrl/viewer`](/docs/packages/viewer#baked-lights) draws it while the
scene's lighting has the same signature.

`bakedLightsSignature(lighting)` covers the lights that are on, with their
placement after **Turn**, size, strength and color. It leaves out the
environment map and its brightness, which scale baked light at draw time just
as they scale live light.

## Requirements

`@vctrl/core` runs wherever ES modules load: any current bundler, browser, Web Worker
or Node.js. Loading it with `require()` needs Node.js 20.19, 22.12 or later, with the
`instanceof` caveat under Installation.

`sharp` is **optional**, not required. Install it only to enable native server-side texture compression; without it, `compressTextures` falls back to basic optimization (see the note at the top of this page). Browser and edge callers inject their own encoder, `createBrowserTextureEncoder()` from `@vctrl/hooks` being the ready-made one, and need no native build.
