### Before You Begin

The Vectreal Publisher is available at [vectreal.com/publisher](https://vectreal.com/publisher). No account is required to upload and configure a model - you will only be prompted to sign in when you want to save a scene to your account and publish it.

If you want to follow along, grab any GLB or glTF file you have on hand. If you do not have one, the [three.js editor](https://threejs.org/editor/) can export examples, or you can pull a model from [Khronos glTF samples](https://github.com/KhronosGroup/glTF-Sample-Assets).

---

### Step 1 - Upload

![Uploading a model](/assets/images/newsroom/02/01-publisher-upload.jpeg)

Drag your 3D file onto the Publisher canvas. The parser identifies the format, resolves any external references, and loads the model into the viewport.

**Supported formats:**

| Format | Extension(s) | Notes |
|---|---|---|
| GLB | `.glb` | Self-contained binary glTF - easiest to share, single file |
| glTF | `.gltf` + `.bin` + textures | Full material and animation support; preferred format |
| USDZ | `.usdz` | Limited support - textures and some material types may not render correctly. Work in progress. |

Those three are the whole list. OBJ, FBX and STL do not load, so convert to glTF or GLB first.

**glTF bundles:** glTF separates geometry, binaries, and textures into multiple files. To upload a full bundle, drag the **entire folder** onto the upload area, or select all files at once in the file picker. The parser identifies the `.gltf` root and resolves all referenced `.bin` and texture files automatically.

There are no hard file size limits enforced in the Publisher UI, though very large files (above 500 MB) may slow browser-side parsing. For production-grade assets, the optimization step in the next section helps significantly.

**Common upload errors:**

| Error | Likely cause | Fix |
|---|---|---|
| "Unsupported file format" | Extension not in the supported list | Convert to GLB or glTF |
| "Failed to parse file" | Corrupt file or missing references | Verify the file opens in a local viewer |
| "Missing binary or texture" | Uploaded `.gltf` without `.bin`/textures | Upload the full folder as a bundle |

### Step 2 - Optimize

![Optimizing a model](/assets/images/newsroom/02/02-publisher-optimize.jpeg)

Once your model is in the viewport, the right sidebar shows the quality presets. These are the fastest way to reduce file size for web delivery.

**Quality presets:**

| Preset | Texture resolution | Texture quality | Use when |
|---|---|---|---|
| Maximum quality | 2048 px | 90 | High-fidelity product display |
| Balanced | 1024 px | 80 | Recommended for most web experiences |
| Smallest | 512 px | 70 | Maximum performance, lightweight pages |

All three share the same geometry pipeline: duplicate removal plus Draco compression, both always on. The only thing a preset changes is texture resolution and quality.

Presets are **non-destructive**: switching between them re-processes from the original uploaded file. Nothing is lost. Advanced users can override texture values, and opt into mesh simplification, in the settings panel.

**What is happening under the hood:**

*Mesh simplification* uses the [glTF-Transform](https://gltf-transform.dev) `simplify` function, where the ratio is the fraction of vertices retained. It is **off in every preset** and opt-in from the advanced panel only, because it changes topology and can leave holes and shading seams.

*Texture compression* re-encodes textures to WebP through `OffscreenCanvas`, hardware-accelerated where available. The viewport preview uses the uncompressed original while compression runs, so you can keep working without waiting.

For server-side optimization (via `@vctrl/core`), Sharp is used for texture compression. When Sharp is unavailable, the pipeline falls back to deduplication and pruning rather than failing.

### Step 3 - Configure

![Composing the scene](/assets/images/newsroom/02/03-publisher-compose.jpeg)

Beyond file size, the Publisher gives you full control over how the scene looks and behaves.

#### Lighting and Environment

Choose from a set of HDR environment presets - including studio, golden hour, and overcast options - that determine ambient lighting, reflections, and image-based lighting (IBL). You can adjust lighting strength, toggle **Show as background**, and tune **Background Blur** and **Background Brightness**. With the background toggle off, the background stays transparent; there is no solid background color setting.

The viewer fits the camera to the loaded model automatically via its bounds logic. There is no user-facing margin control.

#### Camera

There are no x/y/z position inputs. Frame the shot in the viewport, then click **Set camera to current view** to capture the position, rotation, target, and field of view onto the selected camera. Field of view is a three-way preset: Wide (90°), Standard (60°), Telephoto (35°).

**Auto Rotate:** in the **Interaction** tool, enable continuous orbit around the model and set the rotation speed. There is no pause-on-interaction delay.

#### Shadows

Shadows are off by default. The **Shadows** tool has a single **Enabled** switch, then three presets (Soft, Studio, Dramatic) that each set a complete look, plus **Opacity**, **Darkness** and **Softness** sliders to adjust one. A separate **Ground shadow** section adds a soft pool under the model, and **Ambient occlusion** sits behind **Advanced**.

#### Grid

Grid controls are currently not active in the viewer render flow. This section will be updated when grid rendering is available.

### Step 4 - Save the Scene

![Dashboard view](/assets/images/newsroom/02/04-dashboard-recent.jpeg)

Click **Save** in the Publisher header.

- If you are signed in, the scene saves to your account immediately and appears in the Dashboard.
- If you are in an anonymous session, you will be prompted to sign in or create a free account. Your configuration is preserved - nothing is lost.

After saving, the scene appears in your [Dashboard](https://vectreal.com/dashboard), where you can manage multiple scenes across projects.

To load a different model, start from [vectreal.com/publisher](https://vectreal.com/publisher) and drop it on the upload area there.

---

### Step 5 - Publish

![Publishing a scene](/assets/images/newsroom/02/05-publisher-publish.jpeg)

From the Dashboard, open the scene. In the **Publish** sidebar section, click **Publish**.

Publishing transitions the scene from **draft** to **published** status and generates a stable embed URL.

> **Draft scenes are never accessible to external iframe embeds.** They remain viewable only by authenticated collaborators with project access.

To revert, click **Unpublish**. The embed URL becomes inaccessible to external principals immediately.

---

### Step 6 - Set Up a Preview API Key

![Managing API Keys](/assets/images/newsroom/02/06-dashboard-api-keys.jpeg)

External iframe embeds require a **preview API key** scoped to the project that owns the scene. This is how Vectreal ensures scenes can only be embedded by authorized principals - not hotlinked by arbitrary sites.

To create a key:

1. Go to **Dashboard → API Keys**.
2. Click **New API Key**.
3. Select the project(s) the key should have access to.
4. Copy the key - it is shown only once.

Pass the key as the `token` query parameter in the embed URL, or as a `Bearer` token in the `Authorization` header for API requests.

**Restricting embed domains (optional):**

To prevent hotlinking from unauthorized domains, open **Dashboard → Projects**, select your project, click **Edit**, and add entries to **Allowed embed domains**. Supported patterns:

| Pattern | What it matches |
|---|---|
| `example.com` | Exact host only |
| `*.example.com` | All subdomains of `example.com` |

Requests from unlisted domains receive a `403 Forbidden` response. The allowlist is not optional: an **empty** list rejects every external host, so add the domain that will host the iframe before you ship. `localhost` and `127.0.0.1` are valid entries but must be added explicitly if you want to test the embed locally.

### Step 7 - Embed

![Embedding a scene](/assets/images/newsroom/02/07-publisher-embed.jpeg)

Copy the embed snippet from the **Embed** section in the publish sidebar or from the scene detail page in the Dashboard.

**Responsive 16:9 snippet:**

```html
<div style="position:relative;padding-top:56.25%;width:100%">
  <iframe
    src="https://vectreal.com/embed/<projectId>/<sceneId>?token=YOUR_PREVIEW_API_KEY"
    style="position:absolute;top:0;left:0;width:100%;height:100%;border:0"
    allow="autoplay"
    loading="lazy"
  ></iframe>
</div>
```

**Fixed size snippet:**

```html
<iframe
  src="https://vectreal.com/embed/<projectId>/<sceneId>?token=YOUR_PREVIEW_API_KEY"
  width="800"
  height="450"
  style="border:0"
  allow="autoplay"
  loading="lazy"
></iframe>
```

Paste either snippet into any HTML page. The embedded viewer loads your published scene.

**Embeds are served from a single route:**

| Mode | URL pattern | Best for |
|---|---|---|
| Embed | `/embed/:projectId/:sceneId` | Full viewport, immersive presentation |

It supports the `token` query parameter and `Authorization: Bearer` authentication.

### Status Code Reference

Worth bookmarking for debugging:

| Scenario | Status code |
|---|---|
| Missing `projectId` or `sceneId` | `400 Bad Request` |
| Rate limited token validation | `429 Too Many Requests` |
| Disallowed embed domain | `403 Forbidden` |
| Draft or non-existent scene (external access) | `404 Not Found` |
| Invalid or revoked API key | `404 Not Found` |
